# 期待結果（正解データ）

本書は `samples/` 配下に作成した模擬資産の正解データである。混入した欠陥の一覧と、
JCL・プログラム・サブルーチン・データセットの呼出関係の正解を記す。解析エンジンの
自動テストにおいて、検出結果と本書の内容を突き合わせる用途に使う。

行番号はすべて対象ファイルの1行目を1として数える。COBOLソースの1〜6桁の一連番号は
空白であり、実コード（7桁目の指示部を除く8桁目以降の本体）は各行にそのまま記載して
いる。

## 1. 資産構成

解析対象は18本である。内訳はJCL 3本・COBOL本体11本（`cobol/`の9本と`encoding/`の2本）・
コピー句3本・BMSマップ1本で、`cics/`のトランザクション定義表と本書はソースではないため
この数に含まない。走査はフォルダの形を問わず、種別はソースの内容から決まる。

## 4. JCL→プログラム→サブルーチン→データセットの呼出関係（正解）

シンボリックパラメータ`&CYCLE`は各JCLの冒頭で`SET CYCLE=250718`により定義しており、
以下のデータセット名の`&CYCLE`部分は実行時に`250718`へ置換される（例:
`SYKT.D&CYCLE..ORDER.DAILY` → `SYKT.D250718.ORDER.DAILY`）。

### 4.1 SYKD010.jcl（受注データ検証・登録　日次バッチ）

- STEP010（14行目、EXEC PGM=SYK001）
  - 入力: `SYKT.D&CYCLE..ORDER.DAILY`（DD名 ORDIN、16行目、QSAM）
  - 出力: `SYKW.D&CYCLE..ORDER.VALID`（DD名 ORDVALID、17〜20行目、QSAM）
  - 出力: `SYKW.D&CYCLE..ORDER.ERROR`（DD名 ORDERR、21〜24行目、QSAM）
  - SYK001は明細検証時にSYK003を静的CALLする（SYK001.cbl 110行目）。
- STEP020（27行目、EXEC PGM=SYK002、COND=(4,LT,STEP010)）
  - STEP010のRCが4を超える場合は本ステップをスキップする。
  - 入力: `SYKW.D&CYCLE..ORDER.VALID`（DD名 ORDVALID、29行目）＝STEP010の出力データセットと同一であり、
    ステップ間のデータセット連携にあたる。
  - 入出力: `SYKV.ORDER.MASTER`（DD名 ORDMSTR、30行目、VSAM KSDS、キーは`SYK2-受注番号`）
  - SYK002は新規登録時にSYK004を動的CALLする（SYK002.cbl 113行目、CALL対象のプログラム名は
    70行目で`WS-PROG-NAME`に'SYK004'をMOVEして設定する）。

### 4.2 SYKD020.jcl（在庫更新・引当確定　日次バッチ）

- インストリームPROC SYKPRC01（15〜20行目で定義、PGM=SYK007を実行）
- STEP010（22行目、EXEC PGM=SYK006、PARM='&CYCLE'）
  - 入力: `SYKT.D&CYCLE..STOCK.DAILY`（DD名 STKIN、24行目、QSAM）
  - 出力: `SYKW.D&CYCLE..STOCK.EXTRACT`（DD名 STKEXTR、25〜28行目、QSAM）
  - Db2表 `SYKDB.ZAIKOM`（在庫マスタ表）に対してSELECT INTO・UPDATE・INSERTを実行し、
    カーソル`SYKZAIKOCUR`（SYK006.cbl 145〜157行目）でDECLARE・OPEN・FETCH・CLOSEを行い、
    その結果をSTKEXTRへ出力する。
  - SYK006はエラー商品登録時およびINSERTエラー時にSYK005を静的CALLする
    （SYK006.cbl 133行目、142行目）。
- STEP020（31行目、EXEC SYKPRC01,CYCLE=&CYCLE）
  - インストリームPROC SYKPRC01を実行し、内部でPGM=SYK007（16行目）を起動する。
  - 入力: `SYKW.D&CYCLE..STOCK.EXTRACT`（DD名 STKEXTR、18行目）＝STEP010の出力データセットと
    同一であり、ステップ間のデータセット連携にあたる。
  - Db2表 `SYKDB.ZAIKOM`に対してUPDATE、`SYKDB.SOKOM`（倉庫マスタ表）に対してSELECT INTOを実行する。

### 4.3 SYKD030.jcl（受注データ　エラー分再処理バッチ、リラン専用）

- STEP010（13行目、EXEC PGM=SYK001、PARM='&CYCLE,RERUN'）

## 7. 文字コード検証結果

### 7.1 UTF-8版・Shift_JIS版

`samples/encoding/SYKENC1_UTF8.cbl`を正本とし、PowerShellから
`[System.Text.Encoding]::GetEncoding(932)`を用いて`samples/encoding/SYKENC1_SJIS.cbl`へ
変換した。変換後のファイルをcodepage 932でデコードした結果、正本と同一の文字列に
復元できることを確認済みである（UTF-8側993文字に対し、Shift_JIS側1,124バイト）。

### 7.2 EBCDIC版（IBM930／IBM037）

EBCDIC版の作成は見送った。理由は次のとおりである。

- IBM930（日本語カタカナ拡張SBCS/DBCS-host EBCDIC）は、.NET の
  `System.Text.CodePagesEncodingProvider`に登録した状態でも
  `[System.Text.Encoding]::GetEncoding(930)`が「No data is available for encoding 930」
  という例外を返し、この実行環境では利用できないことを確認した（コードページ939も同様）。
- 代替として利用可能なEBCDIC系コードページ（37: IBM EBCDIC US-Canada、1047: IBM Latin-1、
  20290: IBM EBCDIC 日本語カタカナ）でエンコードを試みたところ、いずれも
  `EncoderFallback.ExceptionFallback`指定の下で「Unable to translate Unicode character
  文（"文"）」という例外となり、本サンプルに含む漢字・ひらがなを表現できないことを
  確認した。これらのコードページは半角カタカナまでしか扱えない単バイトEBCDICであり、
  日本語混じりの見出し・コメントを同一内容のまま変換することはできない。
- 以上により、この実行環境で「日本語コメントと日本語混じりの見出しを含む」という
  同一内容を保ったままEBCDIC版を作成する手段はないと判断し、作成を省略した。

## 8. 既知の付随事象（検出正解に含めない参考情報）

本節は、「2. 混入した欠陥一覧」に記す18件の意図的欠陥とは別枠の参考情報である。

## 9. CICS資産の呼出関係

samples/bms/のSYKMAP1.bms、samples/cobol/のSYK008.cbl・SYK009.cbl、samples/cics/のトランザクション定義表.csvは、CICSの疑似会話処理を模した資産である。SYK008・SYK009はCICSトランザクションとして起動するため、対応するJCLを持たない（「1.2 COBOL（samples/cobol/）」参照）。両プログラムの呼出関係を本節に記す。

### 9.1 BMSマップの構成

samples/bms/SYKMAP1.bmsは、マップセットSYKMAP1（DFHMSD、7〜11行目）を定義する。マップセットSYKMAP1は、マップSYKM01（DFHMDI、13行目）を1件持つ。マップSYKM01が持つフィールドは、受注番号入力用のORDNO（DFHMDF、POS=(3,10)、LENGTH=8、ATTRB=(UNPROT,NUM)、15〜17行目）と、メッセージ表示用のMSG（DFHMDF、POS=(22,5)、LENGTH=40、ATTRB=(PROT,BRT)、19〜21行目）の2件である。マップセットSYKMAP1にマップSYKM99は定義されていない。

### 9.2 SYK008・SYK009の呼出関係

| 呼出元 | 呼出方式 | 呼出先／参照先 | 該当行 |
|---|---|---|---|
| SYK008 | EXEC CICS RECEIVE MAP('SYKM01') MAPSET('SYKMAP1') | マップSYKM01（マップセットSYKMAP1） | SYK008.cbl 34〜38行目 |
| SYK008 | EXEC CICS SEND MAP('SYKM99') MAPSET('SYKMAP1') | マップSYKM99（マップセットSYKMAP1に定義されておらず、「2. 混入した欠陥一覧」No.17の欠陥にあたる） | SYK008.cbl 55〜61行目 |
| SYK008 | EXEC CICS XCTL PROGRAM('SYK009') | SYK009 | SYK008.cbl 75〜79行目（XCTLは76行目） |
| SYK008 | EXEC CICS RETURN TRANSID('SYK8') | トランザクションSYK8（samples/cics/トランザクション定義表.csvの対応により、次回のSYK8起動時にSYK008へ制御が渡る） | SYK008.cbl 65〜69行目（RETURNは66行目） |

samples/cics/トランザクション定義表.csvは、トランザクションID`SYK8`とプログラム名`SYK008`を1行で対応づける。この対応関係により、SYK008.cbl 66行目の`EXEC CICS RETURN TRANSID('SYK8')`は、次回のトランザクションSYK8起動時に制御を再びSYK008へ渡し、疑似会話を継続する。

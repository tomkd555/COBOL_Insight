# 06 ルールカタログ

## 1. 本書の位置づけ

本書は、本アプリケーション（COBOL Insight）が検出するバグ検出ルールおよびSQL最適化助言ルールの正本である。各ルールのID・名称・カテゴリ・説明・既定severity・解析段階（バグ検出ルール）または判定方法の要点（SQL助言ルール）を定める。`02_要件定義.md`と`05_開発計画.md`は、ルール個別の仕様について本書を参照する。

初版のルールカタログは、バグ検出ルール31件（R001〜R031）とSQL最適化助言ルール6件（S001〜S006）の合計37件で構成する。

既定severityは本書の値とする。誤検出率の数値許容水準は定めない。全ルールを既定で有効とし、利用者はルール単位で無効化できる。

コードスメル寄りのルール、すなわちバグそのものというより可読性・保守性上の注意点に近いルールは、既定severityを「警告」とする。R009（GO TO文による構造化フローからの逸脱）とR025（二項演算子の両辺が同一の式）がこれに該当する。それ以外のルールは、検出する欠陥の重大さに応じて「高」「中」「低」のいずれかを既定severityとする。

## 2. バグ検出ルール一覧（R001〜R031）

### 2.1 解析段階の区分

バグ検出ルールは、検出に要する解析の深さで3段階に分ける。

- **第1段（構文のみ）**: 構文解析だけで判定できるルール。制御フローグラフの構築や、変数の値・参照経路をたどるデータフロー解析を要しない。該当するルールは7件である。
- **第2段（CFG依存）**: 段落・セクション間の制御フローグラフ（CFG）を構築し、実行経路・到達可能性をたどる制御フロー解析を要するルール。該当するルールは13件である。
- **第3段（データフロー依存）**: 到達定義・値の区間（値域）・汚染追跡・生存の4技法により、変数の値の伝播を追跡するデータフロー解析を要するルール。該当するルールは11件である。

3段階の件数は7件・13件・11件、合計31件である。

## 3. SQL最適化助言ルール一覧（S001〜S006）

### 3.1 判定範囲

SQL最適化助言ルールは、埋め込みDb2 SQLを対象に、構文レベルの判定だけで成り立つ助言に限定する。EXPLAINの実行結果やDb2カタログ（テーブル定義・インデックス定義・統計情報等）を参照する高度な助言は初版の対象外とし、将来拡張とする。

初版は6件（S001〜S006）とし、SELECT *の回避、非SARGableな述語（インデックスによる絞り込みに利用できない述語）の使用、インデックス列への関数適用、カーソルの宣言・後始末、FETCH FIRST句の未使用、OPTIMIZE FOR句の未使用の6主題を定式化する。
